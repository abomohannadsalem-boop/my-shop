# راهنمای نسخه مدیریت‌شده فروشگاه

## امکانات اضافه‌شده
- پنل مدیریت در مسیر `/admin` برای حساب `mrehsanshop@gmail.com`
- ثبت، ویرایش و حذف محصول
- انتخاب دسته‌بندی، قیمت، توضیحات و موجودی
- تبدیل عکس در مرورگر به WebP و بارگذاری در Supabase Storage
- نمایش همه عکس‌های محصول در گالری و رفتن به عکس مرتبط هنگام انتخاب رنگ
- موجودی جداگانه برای هر رنگ محصول، با وضعیت سبز/قرمز در کارت و جزئیات
- نمایش کد محصول در کارت‌ها، جزئیات، سبد خرید، سفارش‌ها و پنل مدیریت
- غیرفعال‌کردن افزودن و افزایش تعداد برای محصول/رنگ ناموجود
- API سبد خرید حساب‌های واردشده و ذخیره در جدول `user_carts`
- سبد خرید مهمان در localStorage و تلاش برای ادغام آن پس از ورود
- کنترل مجوز نوشتن در دیتابیس با Row Level Security (RLS)

## گام اول: تنظیم متغیرها
فایل `.env.local` داخل این بسته قرار دارد و حاوی آدرس پروژه Supabase و کلید publishable است. این فایل شامل رمز عبور ادمین یا کلید service-role نیست؛ این اطلاعات در فایل ZIP اولیه هم وجود نداشتند و نباید در مرورگر یا فایل عمومی قرار گیرند.

## گام دوم: اجرای مهاجرت دیتابیس
1. وارد Supabase Dashboard پروژه فعلی شوید.
2. از منوی SQL Editor یک Query جدید باز کنید.
3. اگر migration قبلی `supabase/migrations/20261014_admin_cart_storage.sql` هنوز اجرا نشده است، ابتدا آن را اجرا کنید.
4. سپس کل محتوای `supabase/migrations/20261014_customer_profiles_product_variants.sql` را اجرا کنید.
5. سپس فایل `supabase/migrations/20261014_auto_product_codes.sql` را اجرا کنید، اگر هنوز اجرا نشده است.
6. در پایان فایل `supabase/migrations/20261014_phone_login_admin_customer_access.sql` را اجرا کنید تا شماره‌های محلی، دسترسی ادمین به پروفایل و سبد خرید و کدهای مشتری هماهنگ شوند.
7. مطمئن شوید جدول `products`، جدول `order_items` و جدول‌های `categories` و `product_media` در پروژه وجود دارند.

در پنل مدیریت، بعد از افزودن هر رنگ، تصویر مرتبط و وضعیت «موجود است/ناموجود» آن را جداگانه تنظیم کنید. برای اینکه کنترل مستقل رنگ‌ها فعال بماند، وضعیت کلی محصول را نیز روشن نگه دارید؛ خاموش‌کردن وضعیت کلی، تمام رنگ‌ها را ناموجود می‌کند. رنگ‌های قدیمی که وضعیت موجودی ندارند، پیش‌فرض موجود در نظر گرفته می‌شوند تا تا زمانی که شما مشخص کنید، محصول قدیمی ناخواسته ناموجود نشود.

Migration اطلاعات رنگ‌ها را ذخیره می‌کند، کد یکتای مشتری را ایجاد می‌کند، اطلاعات کاربران فعلی را تا حد امکان وارد پروفایل می‌کند و مجوز مشاهده پروفایل‌ها و سبد خرید مشتریان را فقط به ادمین مشخص‌شده می‌دهد. Migration جدید تلفن نیز مقدار شماره‌ها را برای نمایش به شکل محلی `09xxxxxxxxx` نرمال می‌کند و دسترسی خواندن پروفایل و سبد کاربران را برای ایمیل ادمین فعال می‌کند. قبل از اجرای SQL روی فروشگاه زنده، از دیتابیس نسخه پشتیبان بگیرید.

## گام سوم: حساب ادمین
در Supabase بخش Authentication > Users بررسی کنید `mrehsanshop@gmail.com` حساب داشته باشد و ایمیلش تأیید شده باشد. سپس با همین ایمیل از صفحه ورود سایت لاگین کنید و `/admin` را باز کنید. این کد حساب را خودش ایجاد نمی‌کند و رمز عبور هم در فایل‌ها ذخیره نمی‌شود.

## گام چهارم: ورود و ثبت‌نام با شماره تلفن، بدون پیامک
1. در Supabase به `Authentication > Sign In / Providers > Phone` بروید و Phone provider را فعال کنید.
2. گزینه‌ی **Confirm phone** را خاموش کنید. این تنظیم ضروری است: تا وقتی تأیید تلفن روشن باشد، Supabase ممکن است پیامک تأیید بفرستد و جلسه‌ی ورود فوری تحویل ندهد.
3. نیازی به پیکربندی سرویس SMS نیست. فرم سایت کادر کد تأیید ندارد؛ کاربر فقط شماره و رمز عبور را وارد می‌کند.
4. شماره در فرم باید دقیقاً ۱۱ رقم باشد و با `09` شروع شود؛ نمونه `09123456789`. رقم‌های فارسی هم پذیرفته می‌شوند و به رقم استاندارد تبدیل می‌شوند. تبدیل به قالب موردنیاز Supabase پشت صحنه انجام می‌شود؛ کاربر نیازی به واردکردن `+98` ندارد.
5. اگر ثبت‌نام موفق شود اما نشست ورود ساخته نشود، تنظیم `Confirm phone` هنوز خاموش نشده یا پیکربندی Auth پروژه نیاز به بررسی دارد. حساب ادمین فعلی همچنان می‌تواند با ایمیل و رمز عبور وارد شود.

## گام پنجم: اجرا در ویندوز
در PowerShell به پوشه پروژه بروید و اجرا کنید:

```powershell
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. برای تست نسخه نهایی نیز `npm run build` را اجرا کنید.

## انتقال مالکیت پروژه Supabase
این کار با تغییر کد انجام نمی‌شود. مالک فعلی باید از تنظیمات سازمان/پروژه Supabase، حساب جدید را به سازمان اضافه کند و در صورت پشتیبانی پلن و ساختار سازمان، مالکیت/دسترسی مدیریتی پروژه را به او بدهد. ممکن است برای انتقال مالکیت نیاز به انتقال پروژه بین سازمان‌ها یا پشتیبانی Supabase باشد. تا زمانی که انتقال کامل و تست نشده، پروژه فعلی را حذف نکنید.

## مهم
- کلید publishable در `.env.local` برای استفاده سمت کاربر طراحی شده؛ امنیت نوشتن با RLS کنترل می‌شود.
- کلید `service_role` را هرگز در کد سمت مرورگر یا مخزن عمومی GitHub قرار ندهید.
- سبد خرید پایدار برای کاربران واردشده پس از اجرای migration کار می‌کند؛ رنگ انتخاب‌شده در سبد و آیتم سفارش هم نگهداری می‌شود. درگاه پرداخت واقعی هنوز به اتصال و تست جداگانه نیاز دارد.
- این نسخه به دلیل نبود دسترسی شبکه در محیط ساخت، در اینجا با `npm run build` تأیید نهایی نشده است. پس از `npm install` روی رایانه خود، build را بررسی کنید.

## تفکیک رنگ‌ها در سبد خرید

- هر ردیف سبد خرید با ترکیب «شناسه محصول + نام رنگ» مشخص می‌شود؛ بنابراین برای یک محصول می‌توان ردیف‌های جداگانه‌ای مانند سفید × ۲ و قرمز × ۳ داشت.
- افزودن دوباره همان رنگ، تعداد همان ردیف را زیاد می‌کند؛ افزودن رنگ متفاوت، ردیف مستقلی می‌سازد.
- شمارنده‌ی +/− روی کارت و صفحه جزئیات، تعداد همان رنگ را نشان می‌دهد و رنگ‌های دیگر همان محصول را با هم جمع نمی‌کند.
- افزودن سریع از کارت، اولین رنگ قابل خرید در فهرست رنگ‌ها را انتخاب می‌کند تا رنگ ناموجود به سبد اضافه نشود.

## کد خودکار محصول (رفع خطای تغییر id)

برای اینکه دیتابیس خودش به هر محصول کدی مثل `PRD-000025` بدهد، فایل `supabase/migrations/20261014_auto_product_codes.sql` را در SQL Editor پروژه‌ی Supabase اجرا کنید. این migration برای محصولات فعلی هم کد می‌سازد، کد را یکتا می‌کند و کد محصول را در ردیف سفارش ذخیره می‌کند.

**ستون `products.id` را دستی تغییر ندهید.** این ستون شناسه‌ی داخلی و identity است؛ کد قابل نمایش محصول در ستون مستقل `product_code` قرار می‌گیرد. این کد هنگام ایجاد محصول خودکار تولید می‌شود و از فرم مدیریت وارد نمی‌شود.

## نام فروشگاه و ایمیل تماس
- نام نمایشی فروشگاه در هدر، صفحه اصلی، عنوان مرورگر و فوتر `Golden Lion` است.
- ایمیل تماس و پشتیبانی `mrehsanshop@gmail.com` است.
- فرم تماس فعلی با زدن «آماده‌کردن ایمیل و ارسال»، برنامه‌ی ایمیل پیش‌فرض کاربر را با گیرنده و متن پیام از قبل پرشده باز می‌کند. برای ارسال مستقیم از داخل سایت بدون بازشدن برنامه‌ی ایمیل، باید سرویس ارسال ایمیل سمت سرور (مثل SMTP یا Resend) و کلیدهای آن جداگانه پیکربندی شود.
- فعال‌کردن Phone Provider باید از داشبورد Supabase انجام شود: Authentication > Providers > Phone. این تنظیم از داخل فایل‌های سایت قابل فعال‌کردن نیست.


## گام ششم: محافظت‌های امنیتی
- هدرهای امنیتی مرورگر در `next.config.ts` تنظیم شده‌اند و برای APIهای سبد خرید، ثبت سفارش و خرید ویدیو، محدودیت نرخ درخواست، ردکردن مبدأ cross-origin برای درخواست‌های تغییردهنده، و محدودیت اندازه‌ی بدنه اضافه شده است.
- محدودکننده‌ی درون‌برنامه‌ای حافظه‌ای و وابسته به هر نمونه‌ی سرور است؛ به‌تنهایی محافظ DDoS محسوب نمی‌شود و در چند نمونه‌ی سرور هماهنگ نیست.
- برای احراز هویت که مستقیماً به Supabase ارسال می‌شود، به `Authentication > Rate Limits` بروید و محدودیت نرخ ثبت‌نام/ورود و توکن را بررسی کنید. این محدودیت‌های Supabase بر اساس IP بخشی از حفاظت موجود Auth هستند.
- اگر فروشگاه را عمومی و آنلاین منتشر می‌کنید، CDN/WAF و محدودسازی درخواست در لایه‌ی هاست را هم فعال کنید (مثلاً Cloudflare یا ابزار محافظتی ارائه‌دهنده‌ی هاست). کلید `service_role` را در کد مرورگر یا فایل‌های عمومی قرار ندهید.
- پنل مدیریت: `http://localhost:3000/admin` در اجرای محلی، یا `/admin` روی دامنه‌ی منتشرشده. فقط با حساب ادمین `mrehsanshop@gmail.com` وارد شوید. برای نمایش پروفایل مشتریان و سبدهایشان، migration دسترسی ادمین که در گام دوم ذکر شده باید اجرا شده باشد.


## مدیریت ۵ بنر صفحه اصلی
برای فعال شدن امکان تغییر ۵ تصویر بنر از پنل مدیریت، فایل `supabase/migrations/20261017_storefront_banners.sql` را در SQL Editor پروژه Supabase اجرا کنید. تصاویر از همان فضای ذخیره‌سازی `product-images` که برای عکس محصولات استفاده می‌شود بارگذاری می‌شوند. اگر هنوز migration اجرا نشده باشد، سایت پنج تصویر نمونه محلی را نشان می‌دهد.
